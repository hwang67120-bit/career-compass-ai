# 학습 데이터 기준 자료

## 목적과 범위

이 문서는 나중에 분류·임베딩 모델을 학습·개선할 때 사용할 데이터가 갖춰야 할 기준을 정의한다. **실제 채용공고·회사 데이터를 어디서 가져오는가(크롤링·사용자 입력·API 제휴)는 이 문서의 범위가 아니다** — 그건 별도로 확인 필요 상태로 남아 있다. 여기서 다루는 "학습 데이터"는 사용자가 확정한 프로필, 검증된 채용공고, 사람이 판정한 정답 자료처럼 **모델 개선에 실제로 쓰일 데이터**를 가리킨다.

## 데이터 출처 원칙

- 학습 후보는 사용자 동의, 개인정보 제거와 품질 검사를 모두 통과한 데이터만 사용한다.
- Python은 학습 후보를 직접 만들지 않고 Java에서 검증을 거쳐 전달받는다.
- 사용자가 추출 결과를 수정했다는 사실 자체만으로 정답으로 확정하지 않는다. 수정 데이터는 검증 상태와 사용 목적을 별도로 관리한다.
- 다른 LLM(Ollama 또는 Gemini)의 판정만 받은 자료는 학습 자료로 사용하지 않는다. 판정 주체는 규칙, 사람, 고정 정답 자료, LLM 판정을 구분해서 기록한다.

## 데이터 분할 기준

- 학습·검증·평가 자료를 분리한다.
- 같은 사용자, 같은 공고 또는 거의 동일한 문서가 서로 다른 데이터 분할에 중복되지 않게 한다 (분할 누수 방지).
- 평가 자료는 모델이 학습 중에 보지 못한 고정 자료를 사용한다.
- 계산할 정답 자료가 없는 지표는 임의의 값으로 채우지 않고 측정 불가로 기록한다.

## 학습 자료 검증 항목

다음을 검사해 통과하지 못한 자료는 학습 후보에서 제외한다.

- 빈 라벨
- 모순된 라벨
- 중복 자료
- 출처 누락
- 개인정보(연락처, 주소, 분석 목적에 불필요한 개인 식별 정보) 잔존 여부

## 라벨 신뢰도 구분 (판정 주체)

학습 후보에는 다음 중 어떤 주체가 그 라벨을 판정했는지 함께 기록한다.

| 판정 주체 | 설명 | 학습 자료로 바로 사용 가능한가 |
|---|---|---|
| 고정 정답 자료 | 사람이 사전에 작성한 정답 | 예 |
| 사람 검토 | 자동 판정 불가로 분류된 뒤 사람이 확인 | 예 |
| 규칙 | 코드로 검증 가능한 규칙(스키마, 근거 존재 여부 등) | 예 |
| LLM 판정만 있음 | 다른 LLM의 결과와 비교했지만 사람·규칙 확인이 없음 | 아니요 |

## 버전 관리

- 학습·평가 자료는 버전을 갖는다. 자료 버전이 바뀌면 이전 평가 결과와 비교할 때 버전 차이를 함께 기록한다.
- 각 평가 실행에는 실험 식별자, 실행 시각, 평가 자료 버전과 분할 정보, 모델·프롬프트·스키마 버전을 함께 남긴다.
- 지표 이름과 계산식 자체도 버전으로 관리한다.

## 메인 LLM 학습 제한

- 개인 취향이나 특정 회사 하나의 문서 형식을 반영하기 위해 메인 LLM(Ollama·Gemini)을 즉시 재학습하지 않는다.
- 재학습은 분류·임베딩·중복 탐지처럼 제한된 모델에만 적용하고, 충분히 검증된 데이터가 쌓인 뒤에만 검토한다.

## 확인 필요

- 학습·평가 자료의 실제 저장 위치와 파일 형식 (`datasets/` 폴더 구조는 코덱스가 제안했으나 아직 확정되지 않음)
- 개인정보 제거를 자동으로 확인하는 구체적인 방법(규칙 기반 필터링 범위 등)
- 위 "라벨 신뢰도 구분" 표는 노션 문서의 원칙을 정리한 초안이며, 실제 데이터베이스·파일 스키마로는 아직 확정되지 않았다.
