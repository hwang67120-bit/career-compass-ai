# 오차 범위 계산과 보정

이 문서는 `AGENTS.md`의 `docs/architecture` 정의에 따라 삭제되지 않고 유지되는 아키텍처 설명이다. [training-data-standards.md](training-data-standards.md)에 정의된 기준을 만족하는 데이터가 충분히 쌓인 뒤에만 적용 대상이 되며, 그 전까지는 설계로만 존재한다.

## 목적과 범위

이 문서는 "AI가 계산한 점수(유사도·추출 신뢰도)와 사람이 실제로 확정한 적합도 사이의 오차를 어떻게 측정하고 줄이는가"를 정의한다. **후보를 어떤 순서로 재정렬할지(리랭킹)는 다루지 않는다.**

## 절대 하지 말아야 할 것 — 이미 확정된 원칙

코덱스의 `docs/analysis-responsibility-boundaries.md`에서 이미 확정한 내용이다.

- 조건 일치율은 합격 점수나 합격 확률이 아니다.
- 주요 업무·기술·프로젝트의 의미 유사도는 조건 일치율에 포함하지 않는다.
- 조건 일치율과 의미 유사도를 하나의 불투명한 총점으로 합치지 않는다.

오차 보정도 이 원칙을 그대로 따른다 — **보정 결과가 "합격 확률" 같은 단일 총점으로 둔갑하면 안 된다.** 보정은 각 항목(유사도 점수 등)의 오차를 줄이는 것이지, 새로운 종합 점수를 만드는 것이 아니다.

## 오차 보정 모델

- 입력: Ollama·Gemini의 추출 신뢰 정보, 업무·기술 유사도, 경력 조건과 근거 검증 결과.
- 목표: 사람이 확정한 적합도와 AI 점수 사이의 오차를 줄인다.
- 시작 방식: 해석 가능한 회귀 또는 분류 모델로 시작한다. PyTorch 같은 복잡한 모델은 데이터와 비교 결과가 충분히 쌓인 뒤에만 실험한다.
- 적용 기준: 보정 전후의 오차와 등급 일치율이 실제로 개선되지 않으면 적용하지 않는다. "일부 지표만 좋아졌다"는 이유로 자동 적용하지 않는다.

## 측정 지표

| 지표 | 대상 |
|---|---|
| 정밀도·재현율·F1 | 정보 추출 |
| 클래스별 점수, Macro F1 | 분류 |
| Recall@K, Mean Reciprocal Rank, nDCG | 검색 |
| 정밀도·재현율·F1 | 중복 탐지 |
| 근거 일치, 사실 오류, 확인 안 된 단정, 금지 표현 발생 여부 | 설명 품질 |
| 보정 전후 평균 오차, 등급 일치율 | 오차 보정 자체 |
| Ollama·Gemini 승리율, 동시 통과율, 동시 실패율, 사람 검토 필요율 | 두 모델 비교 |

- 계산할 정답 자료가 없는 지표는 임의의 값으로 채우지 않고 **측정 불가**로 기록한다.
- 지표 이름과 계산식 자체도 버전으로 관리한다 ([training-data-standards.md](training-data-standards.md)의 버전 관리 원칙과 동일).

## 성능 저하 방지

- 학습 자료와 최종 평가 자료를 분리한다 ([training-data-standards.md](training-data-standards.md) 참고).
- 모델이 보지 못한 고정 평가 자료로 새 모델을 검사한다.
- 새 모델은 제한된 요청에서 먼저 비교하고, 이전 안정 모델을 유지한 채 문제가 확인되면 복구한다.

## 확인 필요

- 사람이 확정한 "적합도"를 실제로 어떻게 수집할지 (화면 흐름, 몇 점 척도인지 등 UX 설계와 맞물림 — 아직 없음)
- 회귀/분류 모델의 구체적인 알고리즘과 특징(feature) 목록
- "개선됐다"고 판단할 임계값(오차·등급 일치율 기준 수치)
- 이 계산이 실제로 시작될 수 있는 최소 데이터 규모
