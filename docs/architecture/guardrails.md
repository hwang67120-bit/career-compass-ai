# 가드레일 원칙

이 문서는 `AGENTS.md`의 `docs/architecture` 정의에 따라 삭제되지 않고 유지되는 아키텍처 설명이다. 계층 정의는 [layer-terminology.md](layer-terminology.md)의 `guardrails/`(독립된 상하 계층이 아니라 입출력 경계에 적용되는 정책 영역) 정의를 따른다.

노션 "Python AI 분석 구현 문서"의 "근거 없는 출력 차단" 원칙을 아래 네 가지로 구체화한다.

## 1. 투명성 원칙

시스템이 확인한 것과 확인하지 못한 것을 명확히 구분해서 응답한다. 확인하지 못한 부분을 추측으로 채우지 않는다.

## 2. 자료 없음 명시 규칙

프롬프트에 근거가 없는 항목은 빈 값으로 조용히 넘기거나 그럴듯하게 지어내지 않고, "정보 없음"으로 명시한다.

## 3. 접속·읽기 실패 처리

URL 접속 실패나 데이터를 읽지 못한 경우, 실패 이유를 추측하지 않고 "정보 없음/접속 실패"로만 응답한다.

예시: Gemini `url_context` 도구의 `url_retrieval_status`가 `URL_RETRIEVAL_STATUS_SUCCESS`가 아니면, 모델이 응답 텍스트 안에서 실패 이유를 추측(예: "아마 비공개 저장소인 것 같다")하더라도 그 추측은 근거 없는 내용이므로 가드레일 응답에 포함하지 않는다. `url_retrieval_status` 자체는 실패 이유를 구분하지 않고 `URL_RETRIEVAL_STATUS_ERROR`로만 반환하므로("저장소가 비공개다"라고 확정할 근거가 없음), 사용자에게는 주소 오타·삭제·비공개 세 가능성을 모두 안내하는 일반 문구를 사용한다.

> "저장소에 접속할 수 없습니다. 주소가 정확한지, 저장소가 삭제되지 않았는지, 공개(Public) 설정인지 확인해주세요."

## 4. 등록된 도메인 정보만 조회

LLM이 일반 지식이나 학습 데이터로 답을 채우지 않고, 오직 Java가 실제로 등록·전달한 자료 안에서만 근거를 찾는다.
