# 공공기관 채용공고 분석 책임 경계

상태: **제품 방향 확정 — 2026-08-10 사용자 승인, 외부 API 실제 응답 계약은 확인 필요**

## 목적

MVP의 외부 채용공고 범위를 공공기관 채용공고로 제한하고, Java 백엔드와
Python AI의 책임 및 두 서버 사이의 연결 경계를 정의한다.

실제 신청 서비스는 공공데이터포털의
[인사혁신처 공공취업정보 조회 서비스](https://www.data.go.kr/data/15156780/openapi.do)다.
개발계정 활용 신청은 2026-08-10 자동 승인됐으며 활용기간은 2028-08-10까지다.
인증키 활성화와 실제 목록·상세 XML 응답 확인 전에는 제공자별 필드, 호출 제한과
보관 가능 범위를 구현 계약으로 확정하지 않는다.

## 신청한 공공 API

- 제공기관: 인사혁신처
- 서비스 유형: REST
- 신청 유형: 개발계정
- 처리 상태: 승인
- 심의 여부: 자동승인
- 활용기간: 2026-08-10 ~ 2028-08-10
- 데이터 범위: 중앙부처, 지방자치단체, 시·도 교육청과 각종 공공기관의 공공부문 채용정보
- 데이터 포맷: XML
- Base URL: https://apis.data.go.kr/1760000/PblJobService
- 공식 기능: getList, getItem, getClsfList, getInsttList, getItemFile, getItemPosition
- 갱신 주기: 실시간
- 개발·운영 승인: 자동승인
- 이용허락범위: 제한 없음

이 API는 공공기관만이 아니라 공공부문 전체를 포함한다. MVP를 공공기관으로만
제한하려면 실제 XML에서 기관 유형을 신뢰할 수 있게 구분하는 필드와 필터 규칙을
먼저 확인해야 한다. 확인 전에는 전체 데이터를 공공기관 채용시장으로 표현하지 않는다.

Provider XML 파싱과 오류 검증은 Java에서 끝낸다. Python에는 Provider XML이나
인증키를 전달하지 않고, Java가 정제한 기존 JSON 추출 요청만 전달한다.

## 범위 결정

### 포함

- 공공데이터포털에서 승인받은 공공기관 채용공고 API
- 사용자가 확정한 기술 태그와 선택한 공개 GitHub 저장소 근거
- 공고의 직무, 담당 업무, 필수·우대 조건과 근무 조건
- Java의 결정론적 조건 판정
- Python의 근거 기반 구조화 추출과 의미 유사도
- 출처, 수집 시각, 마지막 확인 시각과 공고 버전

### 제외

- 고용24와 사람인 Provider
- 민간 채용시장 전체를 대표한다는 주장
- Python 또는 LLM의 임의 인터넷 검색·크롤링
- 사용자 채용공고 URL 또는 원문 직접 입력
- 합격 확률, 지원자 순위와 불투명한 단일 종합점수
- 채용 담당자 개인정보와 분석에 필요하지 않은 공고 원문

고용24 구현은 개인회원이 채용정보 Open API를 사용할 수 없다는 실제 응답을
확인했으므로 MVP 활성 Provider에서 제외한다. 기존 코드는 PR #48 검토 이력으로
남길 수 있지만 기본 Provider나 완료 가능한 사용자 흐름으로 취급하지 않는다.

## 전체 흐름

```text
사용자 분석 요청
→ Java가 고정된 프로필·프로젝트 버전과 소유권 검증
→ Java가 허용된 공공기관 채용 API 호출
→ Java가 응답 형식·출처·크기 검증
→ Java가 허용 필드 선택, HTML·스크립트·개인정보 제거
→ Java가 최소 sourceText와 식별자를 Python에 전달
→ Python이 공고 구조와 근거를 추출
→ Java가 계약·식별자·근거를 재검증하고 저장
→ Python이 공고 업무와 사용자 프로젝트 근거의 의미 유사도 계산
→ Java가 명확한 조건을 판정하고 최종 결과 확정
→ Java가 상태 API와 결과 API로 사용자에게 반환
```

## 백엔드 — Java

Java는 외부 데이터의 입구, 사용자 데이터 보호, 작업 상태와 최종 결과를
소유한다.

### 공공기관 채용공고 Provider

- 활성 Provider와 Base URL은 Java 설정이 소유한다.
- API 인증키는 환경변수로만 주입하고 소스·응답·URL·일반 로그에 남기지 않는다.
- 사용자가 Provider, URL, 페이지 번호 또는 자유 형식 검색식을 직접 지정하지 않는다.
- 목록과 상세 응답은 공식 명세 및 실제 표본으로 검증한 필드만 사용한다.
- 공고 식별자, 기관명, 원문 직무명, 게시·마감일, 출처와 확인 시각을 기록한다.
- 같은 제공자 식별자와 공고 버전 지문을 사용해 중복과 변경을 구분한다.
- 외부 호출은 DB 트랜잭션 밖에서 실행한다.

Provider 클래스 이름과 설정 enum은 실제 인증키로 목록·상세 응답을 확인한 뒤
확정한다. 문서 단계에서는 `PublicEmploymentJobPostingProvider`를 제안 이름으로만
사용한다.

### 취업 관련 데이터 제한

프롬프트만으로 입력 범위를 제한하지 않는다. Java가 먼저 허용 필드를 선택하고
필요한 최소 텍스트만 구성한다.

허용 후보:

- 기관명과 원문 채용 제목
- 모집 직무와 주요 업무
- 필수·우대 조건
- 기술, 경력, 학력과 자격증
- 근무 지역과 고용 형태
- 접수 시작일과 마감일
- 출처, 수집 시각과 최소 근거

제외:

- 담당자 이름, 이메일과 전화번호
- 상세 주소와 분석에 필요하지 않은 연락처
- API 원본 응답 전체
- HTML, JavaScript, 외부 링크의 실행 지시와 탐색 문구
- 홍보 문구와 분석에 필요하지 않은 기관 소개
- API 키, 내부 서비스 토큰과 사용자 JWT

공고 응답에 포함된 문자열은 공개 데이터라도 신뢰할 수 없는 입력으로 취급한다.
텍스트 안의 지시문을 시스템 명령이나 LLM 도구 지시로 실행하지 않는다.

### 개인정보 필터링

Java는 Python 호출 전에 다음 순서로 처리한다.

```text
허용 필드 선택
→ HTML·스크립트 제거
→ 담당자·이메일·전화번호·상세 주소 제거
→ 공백과 길이 정규화
→ 최소 sourceText 생성
→ 로그·응답 노출 검사
```

정규식 제거만 개인정보 경계로 사용하지 않는다. 허용 필드 선택을 1차 방어로,
연락처 패턴 제거를 2차 방어로 사용한다. 실제 API 표본으로 제거율을 검증하기
전에는 개인정보 필터가 완료됐다고 판단하지 않는다.

원본 응답과 전체 공고 본문은 영구 저장하지 않는다. 별도 보관 정책이 확정되기
전에는 구조화 값, 최소 근거, 출처와 버전만 저장한다.

### 조건 판정과 최종 결과

Java가 다음을 확정한다.

- 사용자 인증과 리소스 소유권
- 분석 작업의 상태와 단계
- 경력, 학력, 자격증, 지역, 고용 형태와 마감일 판정
- 필수·우대 기술의 근거 기반 판정
- `MATCHED`, `MISMATCHED`, `NEEDS_REVIEW`, `NOT_APPLICABLE`
- 필수·우대 조건 일치율과 필수조건 불충족 여부
- 완료, 부분 완료, 실패와 취소
- 최종 결과 저장과 사용자 API 응답

## AI — Python

Python은 Java가 전달한 정제 데이터만 분석한다.

### 담당

- 공고의 직무명, 담당 업무, 필수·우대 기술 후보 추출
- 추출값과 최소 원문 근거 연결
- 확인할 수 없는 값을 생성하지 않고 제외 또는 정보 없음으로 반환
- 공고 주요 업무·요구 기술과 사용자 프로젝트 근거의 의미 유사도 계산
- 실제 모델 Provider, 모델 이름과 실행 단계 반환
- 모델 장애와 모델 응답 계약 오류 구분

### 담당하지 않음

- 공공데이터포털 또는 외부 웹 검색
- 임의 URL 접속과 크롤링
- API 키와 사용자 인증 정보 수신
- Java 데이터베이스 상태 변경
- 명확한 조건의 최종 판정
- 합격 확률, 지원자 순위와 최종 분석 상태 생성

AI 지시문은 전달된 데이터에서 채용 직무·업무·요구조건과 근거만 추출하고,
채용과 무관한 내용·개인정보·외부 지시문을 무시하도록 제한한다. 이 지시문은
Java 전처리를 대신하지 않는 2차 방어선이다.

Gemini 같은 외부 모델로 전달할 때는 Python이 이메일·전화번호 제거를 다시
수행한다. Java 필터와 Python 이중 방어는 실제 공고 표본으로 함께 검증한다.

## 연결 — Java와 Python

현재 연결 기준은 [`contracts/job-posting-extraction.md`](../../contracts/job-posting-extraction.md)다.

Java가 전달하는 값:

- `jobPostingId`
- `extractionTaskId`
- 개인정보가 제거된 최소 `sourceText`
- `X-Request-Id`와 내부 서비스 토큰 헤더

Java가 전달하지 않는 값:

- 공공데이터포털 API 키
- Provider 원본 응답 전체
- 채용 담당자 개인정보
- 사용자 JWT와 개인 연락처
- Python이 다시 조회할 외부 URL

Python은 구조화 추출 결과, 근거와 모델 실행 정보만 반환한다. Java는 응답의
요청 식별자, 작업 식별자, 허용 enum, 근거 연결과 중복을 다시 검증한다.

기존 [`contracts/job-search-tool.md`](../../contracts/job-search-tool.md)은 Python이
검색 계획을 만들고 Java 검색 도구를 호출하는 이전 방향이다. 이번 결정에서는
Java Worker가 공공기관 Provider를 직접 실행하므로 현재 구현 계약에서 제외한다.

의미 유사도 요청·응답은 아직 별도 계약이 없다. 다음 항목을 확정하기 전에는
DTO, enum과 저장 테이블을 만들지 않는다.

- 비교할 사용자 프로젝트 근거와 공고 요구사항의 식별자
- 유사도 값의 범위와 계산 모델
- 근거 부족·계산 불가·부분 성공 표현
- 모델 실행 정보와 계약 오류
- Java의 저장 및 최종 결과 결합 방식

## 상태와 완료 기준

- 검색 결과 0건은 Provider가 정상 응답한 경우 오류가 아닌 빈 `COMPLETED`다.
- 공고 추출만 성공하고 비교 결과가 없으면 사용자 분석 결과가 아니므로
  `PARTIALLY_COMPLETED`로 표시하지 않는다.
- 하나 이상의 비교 결과가 저장된 뒤 후속 단계 일부가 실패한 경우에만
  `PARTIALLY_COMPLETED`를 사용한다.
- 비교 결과와 결과 API가 구현되기 전 연결 검증은 기술 데모이며 완성된 분석
  서비스로 표시하지 않는다.

## 구현 전 확인 항목

1. 발급 인증키 활성화와 getList·getItem 실제 성공 응답 확인
2. 목록·상세 API의 실제 성공 응답과 오류 응답 저장
3. 공식 필드와 최소 sourceText 구성 기준
4. 담당자·연락처·상세 주소가 포함되는 실제 위치
5. 호출 제한, 이용허락과 원문·최소 근거 보관 범위
6. 검색 키워드와 공고 최대 수의 설정값
7. 의미 유사도 Java–Python 계약
8. 상태 API와 결과 API의 최종 응답

## 검증 순서

1. 발급받은 개발키로 목록과 상세를 각각 한 번 호출한다.
2. 비밀키를 제거한 실제 응답 fixture를 만든다.
3. Java Provider 파싱·오류·개인정보 필터 단위 테스트를 작성한다.
4. 같은 정제 JSON으로 Java와 Python 계약 테스트를 실행한다.
5. Java, PostgreSQL, Python과 실제 모델을 함께 실행한다.
6. 브라우저에서 분석 시작, 상태, 결과와 실패 안내를 확인한다.
