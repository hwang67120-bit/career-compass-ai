# 공공기관 채용공고 검색 키워드 전략

상태: **제안 — 실제 API 응답으로 검증 전**

## 배경

[`public-institution-job-analysis.md`](public-institution-job-analysis.md)에서 확정한 대로 Java가
인사혁신처 공공취업정보 API를 호출한다. 지금 `JobAnalysisWorker`는 사용자 프로필의
`targetJobTitle`(예: "백엔드 개발자")을 그대로 검색 키워드(`Kwrd`)로 사용한다.

공공기관·공무원 채용은 민간 IT 채용과 직무 명칭 체계가 다르다 — "백엔드 개발자" 같은
민간 표현 대신 "전산직", "전산주사보", "정보시스템 운영" 같은 **직렬 명칭**을 쓴다.
그대로 검색하면 실제로 관련 공고가 있어도 결과가 0건이거나 매우 적게 나올 수 있다.

이 문제는 Python(추출·유사도)이 아니라 **Java의 검색 파라미터 구성 책임**이다 — 공고
본문을 받기 전, 검색 단계에서 걸러지므로 추출 로직이 개입할 수 없다.

## 책임 경계

- 키워드 후보 목록·확장 전략은 Java가 소유한다(결정론적 규칙, LLM 호출 없음).
- Python은 이 문서와 무관하다 — Java가 검색을 마치고 넘긴 공고 본문만 받는다.

## 키워드 확장 후보 (제안, 확인 필요)

사용자 `targetJobTitle`을 그대로 쓰는 대신, 아래처럼 직군별 공공 직렬 키워드를 함께
시도한다. 정확한 매핑은 실제 API 응답(공고 제목·기관명 표본)으로 검증 전까지 추정이다.

| 사용자 `targetJobTitle` (민간 표현) | 함께 시도할 공공 직렬 키워드 후보 |
|---|---|
| 백엔드 개발자 | 전산직, 전산 개발, 정보시스템 개발, SW개발, 소프트웨어 개발 |
| 프론트엔드 개발자 | 전산직, 웹개발, 홈페이지 개발, 정보시스템 개발 |
| 풀스택 개발자 | 전산직, 정보시스템 개발, SW개발 |
| 모바일(Android/iOS) 개발자 | 전산직, 앱개발, 모바일 |
| DevOps / 인프라 엔지니어 | 전산직, 정보시스템 운영, 네트워크, 서버 운영 |
| 데이터 엔지니어 / 데이터 사이언티스트 | 데이터직, 빅데이터, 데이터분석, 통계 |
| AI/ML 엔지니어 | 데이터직, 인공지능, 빅데이터 |
| 보안 엔지니어 | 정보보호직, 전산보안, 보안 |
| QA / 테스트 엔지니어 | 전산직, 정보시스템 운영 |

모든 직군에 공통으로 시도할 상위 폴백 키워드: **"전산"** (공공 직렬 전반을 포괄하는
상위어). 위 매핑에 없는 `targetJobTitle`도 최소한 "전산"은 함께 시도한다.

## 검색 전략 (제안)

1. `targetJobTitle` 원문으로 먼저 검색한다.
2. 결과가 비어 있으면 위 표의 대응 키워드를 순서대로 하나씩 검색한다(OR가 아니라
   순차 시도 — 공공데이터포털 API가 다중 키워드 OR 검색을 지원하는지 확인 필요).
3. 매핑에 없는 직군이면 폴백 키워드("전산")로 검색한다.
4. 모든 시도가 0건이면 빈 결과로 종료한다(오류가 아니다 — 기존 0건 처리 원칙과 동일).
5. 여러 키워드로 얻은 결과는 `idx` 기준으로 중복 제거 후 병합한다.

## 확인 필요

- 실제 API로 위 매핑 키워드들이 진짜 관련 공고를 반환하는지 검증(현재는 추정)
- `Kwrd` 파라미터가 부분 일치인지 정확 일치인지, 다중 키워드(OR) 검색을 지원하는지
- 순차 시도 시 호출 횟수 제한(호출 제한·비용) 고려 — 직군당 몇 개까지 시도할지
- 위 표에 없는 직군(예: 게임 서버, QA 자동화 등)의 키워드 보강
