# 후보 재정렬 (리랭킹)

이 문서는 `AGENTS.md`의 `docs/architecture` 정의에 따라 삭제되지 않고 유지되는 아키텍처 설명이다. [embedding-similarity.md](embedding-similarity.md)에서 계산한 항목별 유사도와 [error-calibration.md](error-calibration.md)의 보정값을 입력으로 사용한다. 채용공고·회사 데이터가 시스템에 들어오는 경로는 이 문서의 범위가 아니며 별도로 확인 필요 상태다.

## 목적과 범위

이 문서는 "여러 후보(채용공고·회사) 중 어떤 순서로 사용자에게 보여줄지"를 정의한다. 벡터를 어떻게 만들고 비교하는지는 다루지 않는다 ([embedding-similarity.md](embedding-similarity.md) 참고).

## 책임 경계 — 이미 확정된 원칙

- **의미 검색과 재정렬은 Python의 책임이다.** 사용자 프로필 또는 선택한 회사·공고와 의미가 가까운 후보를 벡터 저장소에서 찾고, 직무·업무·기술·프로젝트의 항목별 유사도를 바탕으로 후보 순서를 계산해 Java에 전달한다.
- **필수 조건 판정은 Java의 책임이며 Python이 임의로 통과시키지 않는다.** 지역·경력 같은 필수 조건은 Python이 재정렬 과정에서 무시하거나 대신 판정하지 않는다.
- **최종 결과 결합은 Java의 책임이다.** Python이 계산한 순서와 Java의 조건 판정 결과를 하나로 합치는 건 Java 오케스트레이션 계층이 한다 (`docs/analysis-responsibility-boundaries.md`의 처리 흐름 참고).
- 조건 일치율과 의미 유사도는 재정렬 단계에서도 하나의 불투명한 총점으로 합치지 않는다. 순서를 정할 때 두 값을 같이 쓰더라도, 각 값은 응답에서 분리된 채로 남아야 한다.

## 최소 품질 기준과 빈 결과

- 유사도가 최소 기준보다 낮은 후보는 순위에 포함하지 않는다.
- 기준을 충족한 후보가 없으면 빈 결과와 사용한 기준을 함께 반환한다. 순위를 채우기 위해 기준 미달 후보를 억지로 포함하지 않는다.

## 평가를 위한 기록

검색·재정렬 결과는 나중에 [error-calibration.md](error-calibration.md)의 검색 평가 지표(Recall@K, MRR, nDCG)를 계산할 수 있도록 다음을 함께 기록한다.

- 검색된 전체 후보
- 최종적으로 선택(노출)된 후보
- 제외된 후보와 제외 사유
- 사용한 임베딩·재정렬 모델 버전

이 기록이 없으면 나중에 검색 품질을 측정할 방법이 없다.

## 확인 필요

- 직무·업무·기술·프로젝트처럼 서로 다른 항목별 유사도를 하나의 순서로 합칠 때 구체적인 가중치나 우선순위 규칙 (지금은 "항목별 유사도를 바탕으로 계산한다"는 원칙만 있고 정확한 계산식은 없음)
- 동점 처리 기준
- 최소 품질 기준의 구체적인 수치 ([embedding-similarity.md](embedding-similarity.md)와 동일하게 미정)
- 별도의 재정렬 전용 모델(re-ranker) 도입 여부 — 노션 문서에는 "기본 임베딩 검색 평가가 부족한 경우에만 검토"로 조건부 남아 있음
