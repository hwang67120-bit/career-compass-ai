# 합성 개발 직군 채용공고 Fixture(반복 검증용 고정 데이터)

상태: 평가 데이터 v1, 실행 연결 구현 완료 — 운영 공고가 아니며
Mock Provider(가짜 공급자)는 `dev`와 `demo` 프로필에서만 활성화된다.

## 목적

외부 API 상태와 관계없이 채용공고 구조화 추출과 비교 흐름을 반복 검증하기 위한 독자적인
합성 데이터다. 실제 기업·기관명과 공고 문장을 복사하지 않았다.

## 포함 직군

백엔드, 프론트엔드, 게임 클라이언트, Android, 머신러닝, 데이터 엔지니어,
DevOps·클라우드, 정보보안, QA 자동화다. 여러 산업에서 통용되는 비교적 안정적인 직군명을
우선했다.

`LLM 엔지니어`, 프롬프트 엔지니어, AI 에이전트 엔지니어처럼 최근 등장해 회사별 의미가
크게 달라지는 명칭은 v1에서 제외했다. 향후 실제 표본과 직무 정의가 확보되면 별도 버전으로
추가한다.

## 파일과 사용 원칙

단일 원본 데이터는
`contracts/fixtures/synthetic_job_postings_v1.json`에서 관리한다.

- `sourceText`는 현재 채용공고 추출 API에 입력할 수 있는 공고 본문이다.
- `expected`는 모델이 만들어야 할 정답 문장이 아니라, 평가 시 확인할 최소 사실 집합이다.
- 모델 표현이 달라도 원문 근거와 의미가 같으면 평가할 수 있다.
- `companyName`, `fixtureId`와 모든 문장은 가상이다.
- 운영 통계, 실제 채용시장 규모와 특정 회사의 채용 사실로 사용하지 않는다.
- Mock은 외부 데이터 입구만 대체하고 필터·추출·판정·저장 코드를 건너뛰지 않는다.
- Java와 Python이 데이터를 복사해 각각 관리하지 않고 같은 단일 원본을 사용한다.

## 실행 연결 시나리오

1. 서버가 `demo` 프로필이고 `job-search.provider=dev-sample`일 때만 합성 공고
   공급자를 활성화한다.
2. Java는 분석에 고정된 프로필의 `targetJobTitle`(희망 직무)을 검색어로 사용한다.
3. 공급자는 검색어 앞뒤 공백을 제거한 뒤 Fixture의 `title`과 정확히 일치하는 공고만
   저장 순서대로 반환한다.
4. 일치 공고가 여러 건이면 요청의 `display` 상한까지만 반환한다.
5. 일치하는 공고가 없으면 빈 목록을 반환한다. 백엔드 개발자 공고로 대체하거나 LLM으로
   비슷한 직무를 추정하지 않는다.
6. Java는 선택된 공고의 `sourceText`를 기존 개인정보 제거·공고 추출·근거 저장 흐름에
   그대로 전달한다.
7. 프로젝트 담당 업무 후보를 사용자가 확정하면 저장된 공고 담당 업무와 의미 비교한다.
8. 확정된 프로젝트 담당 업무가 없으면 비교 모델을 호출하지 않고
   `USER_EVIDENCE_EMPTY_AFTER_SANITIZATION`으로 완료한다.

초기 연결 대상은 파일에 있는 9개 직군이다. `LLM 엔지니어`, 프롬프트 엔지니어와
AI 에이전트 엔지니어는 v1에 없으므로 검색 결과 0건으로 처리한다.

## 브라우저 결과

- 공고 제목과 회사명에 Fixture 값을 표시한다.
- `공고 담당업무 1` 같은 임시 번호 대신 분석에 사용한 실제 공고 근거 문장을 표시한다.
- 계산된 항목은 가장 관련 있는 사용자 프로젝트 담당 업무 문장과
  `관련 있음` 또는 `관련 없음`을 함께 표시한다.
- 사용자 프로젝트 근거가 없으면 막대그래프를 계산 결과처럼 표시하지 않고
  `확정된 프로젝트 근거가 부족합니다`라고 표시한다.
- 검색 결과가 없으면 `검색된 합성 공고 없음`을 표시한다.

## 검증 상태

- Java 공급자는 공용 Fixture를 읽고 정확히 일치하는 희망 직무만 반환한다.
- 검색 결과 없음, 제외 직무와 `display` 경계를 자동 테스트한다.
- 결과 API는 공고·프로젝트 실제 근거 문장을 함께 반환한다.
- 남은 검증은 서버 재빌드 후 정상·프로젝트 근거 부족·검색 결과 없음의 브라우저 확인이다.
